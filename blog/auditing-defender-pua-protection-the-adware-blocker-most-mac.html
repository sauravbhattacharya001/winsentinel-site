Auditing Defender PUA Protection: The Adware Blocker Most Machines Never Turn On

Potentially unwanted applications — bundlers, adware, fake optimizers — slip past antivirus because they aren't malware. Defender's PUA protection blocks them, but it's off by default. Here's how to audit it and turn it on fleet-wide.

The grayware gap

Most Windows machines have a protection setting that is off by default, costs nothing to enable, and blocks the exact class of software that generates the largest share of helpdesk tickets: potentially unwanted applications. Adware, browser hijackers, fake system optimizers, driver-updater scams, bundled toolbars, cryptominers that arrive as "free" utilities. None of it is technically malware, so traditional antivirus signatures wave it through. Microsoft Defender has a dedicated PUA protection feature for exactly this — and on a default Windows install, it is not turned on.

That is the gap. The software your users actually install — the "free PDF converter" that rewrites the browser homepage, the "PC cleaner" that demands payment to remove threats it invented — lives in the space between "legitimate" and "malicious." PUA protection is the control built for that space, and auditing it is a five-minute job.

What PUA protection actually does

When enabled, Defender evaluates downloads and installations against Microsoft's PUA criteria: bundling, misleading advertising, poor reputation, evasive behavior. A match is blocked or quarantined with a detection named PUA:Win32/..., logged in the Microsoft Defender operational log as Event ID 1116 (detection) and 1117 (action taken). It is not a reputation service bolted on after the fact — it is a real-time decision at install time, which is the only moment that matters, because once a bundler runs, it drops its payloads, changes browser settings, and schedules its own persistence.

Two things to know before you touch it. First, Microsoft Edge has its own download-time PUA block, enabled by default — but it only covers downloads made through Edge. Anything installed from a USB stick, a script, another browser, or a software deployment tool bypasses it entirely. Second, PUA protection has three modes: Disabled, Audit mode (logs what it would have blocked, changes nothing), and Enabled (blocks). Audit mode is the correct first step on any machine you do not fully control.

Auditing the setting on one machine

The fastest check is PowerShell:

Get-MpPreference | Select-Object -ExpandProperty PUAProtection

The result is 0 (disabled), 1 (enabled), or 2 (audit mode). The authoritative source is the registry, which is what Group Policy and MDM write:

Get-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows Defender' -Name PUAProtection -ErrorAction SilentlyContinue

No value present means no policy is managing the setting, and the machine is running whatever the local default is — which, on consumer Windows, is disabled. That absence is itself a finding: an unmanaged setting on an unmanaged machine. If the value is 1, the machine is protected. If it is 2, someone started the audit-mode rollout and never finished it — a common state, and worth closing the loop on.

To see what PUA protection would catch, check the Defender operational log for existing PUA detections even on machines where it is off — Edge's own PUA blocks still log there:

Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Windows Defender/Operational'; ID=1116} -MaxEvents 20 | Where-Object { $_.Message -match 'PUA:' }

If that returns rows, users on that machine are already encountering PUA. The control exists; it just is not switched on.

Turning it on — in the right order

  1. Audit mode first, for one week. Set the policy to audit mode and collect the 1116 events. You are looking for false positives: a legitimate line-of-business installer that Microsoft's criteria flag, or an internal tool with bundling behavior. If your audit log is clean after a week, you have your evidence that enforcement is safe.
  2. Enforce with Group Policy or Intune. The policy is Computer Configuration → Administrative Templates → Windows Components → Microsoft Defender Antivirus → Configure detection for potentially unwanted applications, set to Enabled with the option Block. The equivalent Intune setting is under Defender → "Potentially unwanted app (PUA) protection." One policy, fleet-wide, no per-machine work.
  3. Handle the exceptions properly. If a legitimate installer is flagged, exclude the specific file hash or path in Defender exclusions — never disable PUA protection to accommodate one installer. A blanket off-switch for one noisy app is how the control quietly dies.
  4. Re-audit after rollout. A setting that is on today is off tomorrow after a feature update resets a policy, a machine is reimaged without the GPO applied, or a user with local admin rights "fixes" a blocked installer. PUA protection is a configuration state, and configuration states drift.

Why this one is worth your time

PUA is not the most dangerous thing on a Windows machine. It is the most common thing. It is the support-scam popup that convinces a user to call a fake Microsoft number, the browser hijacker that funnels searches through an affiliate, the "optimizer" that is a downloader for something worse. Every one of those incidents costs a helpdesk ticket, a reimage, or a compromised credential — and every one of them is preventable by a setting that ships in the box, free, already installed, and switched off.

That is the pattern worth internalizing: the highest-value hardening work on Windows is rarely buying a new tool. It is auditing the controls you already own and finding the ones that were never turned on. WinSentinel's audit checks Defender configuration — including PUA protection — on every machine it runs on, so a single audit tells you which machines are protected and which are running with the gap open. On a fleet, that same check across every node is what turns a one-machine finding into a rollout: the machines with PUA protection off are the list, and the list is the work.

The setting is free, the audit takes five minutes, and the threat it blocks is the one your users meet every week. Turn it on in audit mode today, enforce it next week, and re-check it after every feature update.
