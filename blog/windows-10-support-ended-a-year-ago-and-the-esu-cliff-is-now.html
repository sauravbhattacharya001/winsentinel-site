Windows 10 Support Ended a Year Ago and the ESU Cliff Is Now a Fleet Problem

Windows 10 left support in October 2025 and first-year ESU has expired, so every remaining machine needs a migration or enrollment decision — here is how to find them before attackers do.

Windows 10 reached end of support on October 14, 2025. That date is now more than a year behind us, and the first year of Extended Security Updates has expired with it. If your fleet still contains Windows 10 machines in late November 2026, you are no longer in a grace period. You are in a decision window with a price tag attached, and attackers know it.

This is not a theoretical deadline. End-of-support operating systems accumulate unpatched vulnerabilities every month, and each Patch Tuesday widens the gap between a supported build and an abandoned one. A machine that stopped receiving security fixes in October 2025 has now missed over a year of kernel, LSASS, SMB, and browser-adjacent patches. Internet-facing or not, that machine is a liability the moment it touches email, a shared drive, or a help-desk remote session.

What the ESU cliff actually means

Microsoft offers Extended Security Updates for Windows 10 as a paid bridge, priced per device and rising each year. Year one covered October 2025 through October 2026. Organizations that enrolled must now renew at year-two pricing, migrate the hardware to Windows 11, replace it, or isolate it. Organizations that never enrolled have been running unpatched for over a year, whether they realized it or not.

Three failure modes show up repeatedly in audits:

  • The forgotten machine. A lab PC, a warehouse terminal, a conference-room box, or a virtual machine spun up for one project and never retired. It is domain-joined, it has cached credentials, and nobody owns its patching.
  • The incompatible machine. Hardware that cannot meet Windows 11 requirements — no TPM 2.0, an unsupported CPU, or a line-of-business peripheral with no modern driver. It stays on Windows 10 by default rather than by decision.
  • The assumed enrollment. Someone believes ESU was purchased, but the key was never activated, the device was never enrolled through the proper channel, or the subscription lapsed at the year boundary. The machine looks managed and is not.

All three are inventory problems before they are patching problems. You cannot migrate, enroll, or isolate a machine you have not found.

Find every straggler first

Start with ground truth, not with the spreadsheet. For each Windows endpoint, you need four facts: the OS edition and build, the last successful security update date, whether ESU is actively enrolled and licensed, and whether the hardware can run a supported OS. Active Directory computer objects and DHCP leases will miss offline, off-domain, and newly imaged machines. A per-machine audit does not guess — it reads what the endpoint itself reports.

Decide per machine: migrate, enroll, or isolate

Once the inventory is honest, every Windows 10 machine falls into one of three buckets. Do not let any machine stay in a fourth bucket called later.

  1. Migrate. If the hardware supports Windows 11, upgrade it. Prioritize machines that handle email, browsing, credentials, or remote access. Verify after the upgrade that update policies, Defender posture, and disk encryption survived the transition — an in-place upgrade that silently drops a hardening setting is a regression, not a migration.
  2. Enroll. If the machine must stay on Windows 10 for a defined business reason, enroll it in ESU properly and verify activation on the endpoint itself. Record the enrollment expiry alongside the asset record so next year renewal is a calendar event, not a surprise. Treat ESU as a bridge with a demolition date, not as a permanent plan.
  3. Isolate. If the machine cannot be upgraded or enrolled, remove it from the general network. No email, no web browsing, no domain credentials with broad rights, no SMB shares to the rest of the fleet. Segment it, allowlist its one job, and audit it more often, not less. An isolated legacy box with tight controls is a managed risk. The same box on the flat LAN is an incident waiting for a date.

Harden what must stay

For machines that remain on Windows 10 under ESU or isolation, compensating controls carry the load that patches no longer can. Enforce SMB signing and disable SMBv1. Turn on Attack Surface Reduction rules and Controlled Folder Access. Remove standing local admin rights and rotate the local administrator password. Disable legacy authentication paths where you can, restrict Remote Desktop to jump hosts, and forward event logs off the box so tampering with the endpoint does not erase the evidence. None of this makes an unsupported OS supported — it buys time and shrinks blast radius while the migration completes.

An end-of-life operating system is not a static risk. It gets worse every month, on a schedule attackers can read as easily as you can.

The practical checklist for this month

  • Produce a per-machine list of OS build and last-patch date; reconcile it against your asset inventory and investigate every gap.
  • Verify ESU enrollment on the endpoint, not in the purchasing portal. A license you own but never activated patches nothing.
  • Assign every Windows 10 machine an owner and a bucket — migrate, enroll, or isolate — with a date attached.
  • Re-audit after each migration wave. Upgrades change posture; confirm the new build inherited your hardening instead of assuming it did.
  • Watch for drift. Retired machines come back from storage, loaners return from the field, and old images get redeployed. Continuous fleet visibility catches the regression the week it happens, not at the next annual audit.

The Windows 10 era ended in October 2025. The ESU bridge was always temporary, and its first span is now behind us. The organizations that handle this well are not the ones with the biggest budgets — they are the ones with an honest inventory and a decision recorded for every machine. Audit the box in front of you today, roll the results up across the fleet, and close the stragglers before an attacker inventories them for you.
