Auditing Windows Remote Assistance: The Help Desk Backdoor Hiding in Plain Sight

Windows Remote Assistance is a signed, built-in remote control tool most admins never audit — here is what WinSentinel checks and how to lock it down.

The Support Tool That Bypasses Your Perimeter

Every Windows machine ships with a built-in remote control tool that most admins never audit: Remote Assistance. Originally designed so a help desk could take over a user's desktop with an invitation, it is still enabled by default on many builds, still listens for inbound connections, and still grants full interactive control of the session — keyboard, mouse, screen, and clipboard included. An attacker who can trigger or hijack a Remote Assistance session does not need to find a vulnerability. They just need to be invited in.

WinSentinel's Remote Assistance audit checks this surface on the machine itself. It inspects the registry keys that govern the feature (fAllowToGetHelp and fAllowFullControl), whether unsolicited Remote Assistance is permitted, and whether the firewall rules that allow inbound Remote Assistance traffic are active. It is one of WinSentinel's 64 audit modules, and it runs locally on the machine — the full audit is part of the free single-machine product, not a fleet feature.

Why This Surface Matters

Remote Assistance is dangerous precisely because it is legitimate. Security tooling is tuned to flag malware and exploits, not a signed Microsoft binary opening an encrypted session at the user's request. Three properties make it a quiet favorite for attackers:

  • It is interactive, not just a shell. A Remote Assistance session gives the helper the user's live desktop. That means access to open applications, logged-in sessions, password managers left unlocked, and any file the user can reach — without ever touching the disk.
  • It is social-engineering friendly. The classic flow starts with a phone call: "This is IT support, I need to fix your machine." The victim generates the invitation themselves. No exploit chain, no phishing link, no payload for an EDR to catch.
  • It persists through the obvious controls. Disabling Remote Desktop does not disable Remote Assistance. They are separate features with separate registry keys and separate firewall rules. Admins who audit RDP and stop there leave this door open.

What the Audit Checks

The module examines the configuration that actually decides whether a session can happen:

  1. Remote Assistance enabled at all. The fAllowToGetHelp value under the Terminal Services key. If it is on, the machine can receive invitations.
  2. Full control granted. fAllowFullControl decides whether the helper can only watch or can take the keyboard and mouse. Watch-only is still a data exposure risk; full control is a takeover.
  3. Unsolicited Remote Assistance. The offer-remote-assistance policy lets designated helpers connect without an invitation from the user. On any machine where this is enabled, the human in the loop — the one safeguard the feature has — is gone.
  4. Firewall rules. Inbound rules for Remote Assistance must be active for a session to connect. A machine with the feature on but the firewall rule off is protected by accident, and the next firewall profile change can silently re-expose it.

How to Fix It

For most fleets the correct posture is simple: turn it off. If your help desk does not use Remote Assistance, disable it with Group Policy (Computer Configuration > Administrative Templates > System > Remote Assistance > Configure Offer Remote Assistance and Configure Solicited Remote Assistance), or set the registry values directly on standalone machines. If your help desk does use it, narrow it hard: allow solicited sessions only, deny full control by default, restrict Offer Remote Assistance to a named helper group, and keep the firewall rule scoped to your management network.

Then verify the fix the same way the audit does — on the machine, not in a policy report. Group Policy says what should be true. The registry and the firewall say what is true. WinSentinel checks the latter, so a machine that drifted out of policy shows up as a finding instead of hiding behind a green dashboard.

Remote Assistance is a reminder that the most dangerous remote access tool in your environment may be the one Microsoft installed for you. Audit it like an attacker would: as a door, not a feature.

The Takeaway

Audit the tools your users were given, not just the tools attackers bring. Remote Assistance is signed, supported, and invisible to most detection — which is exactly why it belongs in a routine audit. Run the check, disable what you do not use, and scope tightly what you keep.
